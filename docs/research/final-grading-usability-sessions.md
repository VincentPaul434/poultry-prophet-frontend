# Poultry Prophet: usability session guide

## Purpose

Observe whether real farm managers and handlers can complete important work without coaching. This guide prepares the sessions; it is not evidence that any participants have already taken part.

## Before participants arrive

- Recruit managers and handlers separately. A small exploratory round might start with 5 of each; report the actual number and do not claim statistical representativeness.
- Use a clearly identified test farm with fictional birds, test users and demo inventory. Do not use live farm records or real credentials for destructive tasks.
- Check the test system is online, reset the same starting state for each participant, and prepare a phone and a backup device.
- Explain the purpose, obtain informed consent, and follow your institution's privacy and recording rules. Use participant codes instead of names in notes. Participation is voluntary.
- Tell participants: “We are testing the system, not you. Please say what you expect to happen.” Give the task goal, not the steps.

## Manager tasks

1. Find a batch with overdue work and explain what needs attention.
2. Review a batch's deaths, vaccination status and cost; say whether the cost is complete.
3. Complete a review and find where to record the selection tally.
4. Record a test expense for the correct batch and find it again.
5. Find a completed hatch that needs a batch and create the test batch.

## Handler tasks

1. Find a task assigned to you and mark the test task complete.
2. Record a test health-related death with observed signs; locate the saved record.
3. Record a death when no signs were noticed or when the cause was not observed.
4. Record test product use and explain what happens if stock is insufficient.
5. Record test vaccination or hatch results, according to the permissions and test scenario.

## Record for each task

Record the participant code and role, device, task, start and end times, outcome (**completed unaided / completed with help / not completed**), errors or wrong turns, and any exact comments the participant agrees to have noted. Record what help was given. Do not record fabricated quotes.

After each task ask: “What was confusing?” and “How confident are you that the information was saved?” After the session ask which single change would help most.

## Summarize for the panel

- Give the participant count by role and the test environment/date.
- Show task completion and assistance counts, typical time, and the most common obstacles separately for managers and handlers.
- Separate observed facts, participant comments and researcher interpretations. Explain the small sample's limits.
- List high-impact issues, their reproduction steps, and whether each was fixed and retested. Do not represent simulated or developer tests as real-user sessions.
